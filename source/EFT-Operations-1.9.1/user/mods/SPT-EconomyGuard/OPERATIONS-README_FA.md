# EFT Operations — راهنمای نسخه 1.7.0

## دسترسی به بخش مأموریت‌ها

1. سرور SPT را اجرا کنید.
2. پنل محلی EconomyGuard را باز کنید: `http://127.0.0.1:6970/`
3. با توکن مدیر وارد شوید.
4. از منوی سمت راست/چپ پنل، گزینه **Operations** را باز کنید.

## ساخت مأموریت

- عنوان و نقشه را وارد کنید؛ نام نقشه باید با شناسه مورد استفاده در نسخه بازی/سرور شما هماهنگ باشد.
- حالت Solo، Squad یا Either و حداقل/حداکثر نفرات را تعیین کنید.
- زمان شروع و پایان اختیاری است.
- هدف‌ها را با دکمه Add objective اضافه کنید. نوع هدف، شناسه هدف، تعداد و Required قابل تنظیم است.
- متن Briefing و نوع آن را تعیین کنید. فایل ویدئو/صوت در این نسخه فقط به‌عنوان مسیر/مرجع ذخیره می‌شود و هنوز پخش‌کننده داخل بازی ندارد.
- امتیاز و مبلغ روبل را وارد کنید.
- با Save mission draft ذخیره کنید. پیش از انتشار می‌توانید پیش‌نویس را ویرایش کنید.

## انتشار و Event سایت

با Publish، مأموریت از حالت Draft خارج می‌شود و در صورت فعال بودن StatusBoard، یک خبر از نوع `event` در همان فهرست اعلان‌های سایت عمومی ساخته می‌شود. شناسه این Event به مأموریت متصل می‌شود و با Close کردن مأموریت، Event عمومی نیز غیرفعال خواهد شد. مأموریت منتشرشده در این نسخه قفل ویرایش است؛ برای تغییر محتوای فعال، باید نسخه/گردش انتشار جداگانه اضافه شود.

## فایل JSON

- Export JSON یک تعریف مأموریت را ذخیره می‌کند.
- Import JSON فایل را به‌عنوان پیش‌نویس جدید بارگذاری می‌کند؛ شناسه و وضعیت قبلی فایل برای جلوگیری از بازنویسی تصادفی نادیده گرفته می‌شود.
- نمونه آماده در `Missions/Templates/Squad-Clearance.json` قرار دارد.

## بررسی نتیجه Raid

اگر نتیجه Raid از مسیر معتبر سمت سرور تأیید نشده باشد، گروه به صف `Raid reviews` می‌رود و هیچ امتیازی دریافت نمی‌کند. مدیر باید گزارش/مرجع مدرک را در پنل وارد و نتیجه را Approve یا Deny کند. Approve فقط وقتی ممکن است که تمام هدف‌های ضروری و وضعیت زنده‌ماندن/استخراج همه اعضا در داده نتیجه موجود باشد. بازیکن تا تعیین تکلیف بررسی نمی‌تواند مأموریت دیگری بپذیرد. این تأیید دستی جایگزین ضدتقلب یا اثبات مستقل سرور نیست. در SPT 3.11.1، درخواست پایان Raid شامل `result` و `exitName` است، اما از endpoint کلاینت ارسال می‌شود؛ پس به‌تنهایی مدرک ضدتقلب محسوب نمی‌شود.

## رتبه و پاداش

امتیاز پس از ثبت نتیجه معتبر در دفتر پاداش محاسبه می‌شود و رتبه بازیکن از روی امتیاز تعیین می‌شود. مبلغ روبل و آیتم‌ها فعلاً با وضعیت `pending_delivery` ثبت می‌شوند؛ تحویل خودکار به Stash هنوز پیاده‌سازی نشده است. این نسخه ادعای اتصال کامل مأموریت به رویدادهای درون بازی یا Fika ندارد.

## نکته مهم فنی

پیشرفت هدف‌ها نباید از کلاینت قابل اعتماد گرفته شود. متدهای ثبت رویداد و پایان Raid فقط باید از Adapter سمت سرور SPT/Fika فراخوانی شوند. تا زمان تطبیق با سورس/نسخه دقیق Fika، این بخش به‌صورت API داخلی و غیرقابل فراخوانی از کلاینت باقی مانده است.

## محدودیت اتصال Fika

آرشیو واقعی شما بررسی شد: Fika Server **2.4.3** با `sptVersion: ~3.11` و کلاینت `Fika.Core 1.2.3`. Adapter مشاهده‌گر فقط برای نسخه سرور 2.4.3 فعال می‌شود و read-only است. نسخه 1.8.0 همچنین مسیرهای احراز هویت‌شده SPT را برای فهرست مأموریت، قبول، Ready Check و خروج از گروه در حالت تشکیل اضافه می‌کند. تست عملی روی سرور آزمایشی هنوز لازم است.

## نسخه 1.8.0 — پل ارتباطی امن کلاینت

در این نسخه مسیرهای بازیکن روی Router خود SPT ثبت می‌شوند؛ پنل مدیریتی همچنان فقط روی Loopback و با توکن مدیر باقی می‌ماند. هویت بازیکن از `sessionId` نشست معتبر SPT و شناسه PMC ذخیره‌شده در `SaveServer` استخراج می‌شود؛ API مقدار `profileId` ارسالی کلاینت را مبنای احراز هویت قرار نمی‌دهد.

مسیرهای اضافه‌شده:

- `GET /client/eft/operations/missions` — فهرست مأموریت‌های منتشرشده و فعال
- `GET /client/eft/operations/state` — وضعیت مأموریت، گروه و رتبه بازیکن
- `POST /client/eft/operations/accept` — قبول مأموریت با `missionId`
- `POST /client/eft/operations/ready` — تغییر وضعیت Ready با `groupId` و `ready`
- `POST /client/eft/operations/leave` — خروج از گروه در حالت تشکیل گروه

این API فقط عضویت و Ready Check را مدیریت می‌کند. کلاینت اجازه ثبت Kill/Extract، اعلام موفقیت Raid، شروع گروه، تأیید نتیجه یا صدور جایزه ندارد. گروهی که وارد Raid شده باشد از مسیر Leave قابل ترک نیست. شناسه‌های خصوصی Profile نیز در فهرست اعضای گروه به کلاینت‌ها نمایش داده نمی‌شوند.

برای فعال/غیرفعال کردن API، مقدار `operations.clientApiEnabled` در `config/config.json` را تغییر دهید. برای این مرحله هیچ تغییری روی سرور عملیاتی انجام نشده است؛ ابتدا روی نسخه آزمایشی SPT 3.11.1 بررسی شود.
